# App

A real, `dotnet build`-clean project generated by AspireForge itself, wired into the root
[`AspireForge.slnx`](../AspireForge.slnx) rather than kept as its own solution, and named using
AspireForge's own convention: `App.{layer}`.

```bash
aspireforge new App
aspireforge add postgres
aspireforge add telemetry
aspireforge add authentication
```

## Layout

- `Feature/App.Domain` - entities and business rules with no outward dependencies.
- `Feature/App.Application` - use cases and abstractions, depends only on Domain.
- `Feature/App.Infrastructure` - implementations of Application abstractions (persistence, external services).
- `Feature/App.ServiceDefaults` - OpenTelemetry metrics, traces, logs, and health checks (added by `add telemetry`).
- `Feature/App.Api` - the ASP.NET Core host and composition root.
- `Tests/App.IntegrationTests` - end-to-end tests against the Api.

## Getting started

This project is part of the root [`AspireForge.slnx`](../AspireForge.slnx) rather than its own
solution, so build/test by project path:

```bash
dotnet build Feature/App.Api
dotnet test Tests/App.IntegrationTests
dotnet run --project Feature/App.Api
```

A freshly generated project - `aspireforge new` alone, nothing added - reports **4/10**:

```
Security
  ⚠ Authentication not configured
  ✓ CORS policy restricts origins
  ✓ HTTPS configured

Reliability
  ⚠ Health checks missing
  ⚠ Global exception handling missing

Observability
  ⚠ OpenTelemetry missing
  ⚠ Structured logging missing

Testing
  ⚠ No test project detected
  ✓ Integration tests detected

Architecture
  ✓ No obvious dependency violations

Production Readiness: 4/10
```

This project - the same starting scaffold, then `add postgres`/`add telemetry`/`add
authentication` - reports **7/10**:

```
Security
  ✓ Authentication configured
  ✓ CORS policy restricts origins
  ✓ HTTPS configured

Reliability
  ✓ Health checks configured
  ⚠ Global exception handling missing

Observability
  ✓ OpenTelemetry configured
  ✓ Structured logging

Testing
  ⚠ No test project detected
  ✓ Integration tests detected

Architecture
  ⚠ API directly accesses persistence layer

Production Readiness: 7/10
```

Run `aspireforge doctor Feature/App.Api` yourself to reproduce this. The three remaining warnings are
intentional, not a sample bug: global exception handling and a dedicated unit test project have no
automatic fix yet (see [`fix`](../docs/commands/fix.md#fixable-rules-today)), and the architecture
check flags the Api project's direct EF Core reference - a real, known trade-off of today's
`add postgres`.

## Note on `Directory.Packages.props`

This folder has its own (central package management disabled) so the generated project behaves
exactly as it would outside this repository, rather than inheriting AspireForge's own build
configuration.
